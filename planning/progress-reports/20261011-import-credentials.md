# CC Switch 密钥导入修正

按用户明确要求，已有 API Key 的源记录默认同时导入密钥，环境变量引用作为备选。移除虚构 CC_SWITCH_KEY_n 占位名；没有源密钥时明确提示，选择环境变量必须填写变量名。点击“确认导入（含密钥）”完成确认，不另加复选框；页面说明本机存储与应用后配置/备份写入。预览不暴露密钥。

修复后端将相同源哈希的显式更新错误跳过的问题；现在显式更新可补入密钥，添加的重复防护仍保留。成功反馈区分密钥导入数量与环境变量引用数量。

验证：2 项 Rust 导入专项测试通过（含无确认拒绝并回滚、相同源补密钥不新增连接）；8 项前端测试通过（含有/无密钥默认模式及确认前不写入）；clippy -D warnings、TypeScript/Vite、macOS release 打包与签名完整性检查通过。

按用户授权，使用临时本地辅助程序通过生产 Store.edit 和导入映射读取 CC Switch，依据已有来源标识和相同源哈希匹配，修复 1 条历史占位环境变量连接。只替换该连接凭据，保留其他设置；没有输出密钥，没有改动 CC Switch 或 Droid 目标配置，也没有发送模型请求。临时程序已移除，复查供应商仍为 1 条且凭据模式 direct。

这是 #037/#038 的后续修正，原 Windows 实测待办保持未验证。
